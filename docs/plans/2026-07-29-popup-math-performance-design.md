# 弹窗、数学公式与性能优化设计

日期：2026-07-29

## 已确认的产品方向

- 右键解释结果显示在 Chrome 独立小窗口中，不再占用侧边栏。
- 小窗口使用 `chrome.windows.create({ type: "popup" })`，保留系统标题栏，可移动、缩放；重复解释时复用并聚焦现有窗口。
- 回答中的 LaTeX 公式使用扩展内置 KaTeX 渲染，不加载外部脚本，也不把模型输出作为 HTML 注入页面。
- Native Host 复用一个常驻 `codex app-server` 进程，以减少每次重新启动 Codex 的延迟，并把回答增量实时传给弹窗。
- 默认“均衡”策略使用 GPT-5.6 / medium；用户仍可选择快速、严谨或自定义模型与 reasoning。

## 交互

1. 用户选中文字，右键点击“用 GPT 解释”。
2. 扩展在当前 Chrome 窗口右上方打开约 500 × 720 的独立小窗口；若窗口已存在则直接复用。
3. 小窗口先显示原文和连接状态，随后逐步显示回答。
4. 流式生成时以纯文本更新；短暂防抖后渲染完整的行内或块级公式，生成完成时立即做最终渲染。
5. 关闭小窗口不会取消生成；再次点击扩展图标或右键解释可恢复当前结果。

## 安全与可靠性

- 模型输出先用 `textContent` 写入 DOM，再由本地 KaTeX 只处理数学分隔符。
- KaTeX 使用 `trust: false`、`throwOnError: false`，避免不可信命令和单个坏公式破坏整段回答。
- Codex 线程为临时线程，审批策略为 `never`、沙箱为只读，并在提示词中明确禁止工具调用。
- 仍限制选中文本、提示词、模型名和 Native Messaging 包大小。
- 新请求会中断旧请求；超时会中断对应 turn，而不是反复创建或强杀多个 Codex 进程。

## 性能策略

- 常驻 app-server 消除第二次及后续请求的 CLI 冷启动。
- 使用原生 agent-message delta 做真正的流式展示。
- 公式渲染采用 120ms 防抖，避免每个 token 都触发布局与排版。
- “均衡”默认不牺牲模型质量；“快速”与“严谨”只在用户主动选择时改变模型和 reasoning。

## 兼容性

- 需要支持 `codex app-server` 协议的新版 Codex CLI；安装说明要求 Codex CLI 0.144 或更高版本。
- Chrome 使用 Manifest V3 的 `windows` API；不再请求 `sidePanel` 权限。
