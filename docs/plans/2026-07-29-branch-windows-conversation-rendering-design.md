# 分支窗口、续聊与富文本渲染设计

日期：2026-07-29

## 已确认方向

- 在解释窗口内再次选中文字并使用右键菜单时，新建一个子解释窗口。
- 子窗口继承父窗口已有的原文、解释和对话作为上下文，创建后成为独立分支；子窗口后续对话不会反向污染父窗口。
- 所有解释窗口使用屏幕工作区自动平铺，优先选择与已有解释窗口不相交的空位。
- 每个解释窗口底部提供继续追问输入框，同一窗口的追问复用同一 Codex thread。
- 回答改用本地、安全的 Markdown 与 KaTeX 渲染，支持粗体、斜体、标题、列表、引用、代码、链接和数学公式。

## 状态与窗口

Service Worker 将单一 `currentState` 改为 `resultStates` 字典，每个 `resultId` 对应一个来源、消息列表、运行状态、模型设置和父分支 ID。窗口 URL 包含 `?resultId=...`，因此每个页面只订阅自己的状态。`popupWindows` 保存 `resultId -> windowId`，扩展图标聚焦最近使用的窗口。

创建窗口时，通过 `chrome.system.display.getInfo()` 读取显示器工作区，并读取已登记解释窗口的边界。布局器从来源窗口所在显示器开始，按网格寻找第一个不相交的位置；空间不足时再尝试其他显示器，最后才采用最小错位的候选位置。

## 对话与分支

Native Host 保存 `conversationId -> threadId`。首次解释创建 ephemeral thread；继续追问在同一 thread 上启动新 turn。创建子解释时，扩展把父窗口的有限长度对话快照作为 `parentContext` 传入新 thread 的首个提示词，使它理解被二次选中的内容来自哪段解释，同时从此独立运行。

每个窗口同一时间只运行一个 turn，但不同窗口允许并行生成。取消只中断本窗口对应的 turn，不再全局取消其他窗口。

## 安全渲染

模型输出先经过本地 Marked 转换，再由本地 DOMPurify 使用标签与属性白名单清理。数学片段在 Markdown 解析前临时占位，清理后恢复为文本，最后由 KaTeX 以 `trust: false` 渲染。外部链接强制使用 `noopener noreferrer`，原始模型 HTML 不会直接进入 DOM。

流式输出期间立即显示纯文本，并以 120ms 防抖执行 Markdown/公式排版；turn 完成时立即做最终渲染。

## 失败与恢复

- Native Host 仍会在每个新会话核对账号模型，失效配置回退到账号默认模型。
- Host 重启后旧 thread 不存在；续聊请求携带窗口历史快照，Host 可新建 thread 并恢复必要上下文。
- 关闭一个窗口只移除窗口映射，保留 session 状态；扩展图标可重新打开最近窗口。
- 选中文本、父上下文、追问和单条回答均有长度限制。
